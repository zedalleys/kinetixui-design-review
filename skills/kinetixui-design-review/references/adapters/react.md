# Adapter: React

1. **Detect.** `react`/`react-dom` in `package.json`, `*.tsx|jsx`, hooks (`useState`, `useEffect`), Next/Remix/Vite configs, Storybook for React, `@radix-ui/*`/headless libraries.
2. **Where to look.** Component files and their prop types, `forwardRef`/`asChild`/slot patterns, context providers (theme, direction), `cn`/`clsx`/`cva` variant definitions, CSS Modules/Tailwind/CSS-in-JS styles, story files, `*.test.tsx`, docs examples (MDX), portal usage (`createPortal`, headless-library portals).
3. **Static inspection (V1).** Leads: public prop surface vs docs; controlled/uncontrolled handling (`value`/`defaultValue`/`onChange`); effects that mutate globals or the document root; module-level mutable state shared across instances; unstable object/array props or context values; missing `key`s; missing cleanup in effects; event handlers on non-interactive elements; `dangerouslySetInnerHTML`; hard-coded literals vs tokens; direction/theme provider coverage for portaled content.
4. **Runtime / gated (V2–V3).** Gated: type-check, lint (including a11y lint if configured), unit tests (Testing Library queries by role/name are strong evidence of accessible names), Storybook a11y runs if safe. Runtime: render in a browser (see web adapter); React DevTools profiling for rerender claims.
5. **Idiomatic checks.** Composition over prop explosion; refs forwarded to the interactive element; accessible name on the interactive element, not a wrapper; context for cross-cutting settings (direction, theme) instead of global DOM writes; keys stable; effects only for synchronization.
6. **False positives.** `useEffect` that legitimately synchronizes with an external system; inline styles for truly dynamic values; `any`-typed internals not in the public API; "missing memoization" without a measured problem.
7. **Verification ceiling.** Source → V1. Tests/lint/type-check run → V2 (read what the tests actually assert). Browser → V3. Performance claims need a profile or are INFERENCE.
