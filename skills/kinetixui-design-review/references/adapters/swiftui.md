# Adapter: SwiftUI

1. **Detect.** `Package.swift`/`*.xcodeproj` with `import SwiftUI`, `View` structs, `#Preview` macros, `ViewModifier`, `@State`/`@Binding`/`@Environment`, asset catalogs.
2. **Where to look.** View definitions and their initializers (the API), `ViewModifier`/style protocols (`ButtonStyle`, `LabelStyle`), `@Environment` keys for theme/direction/size class/dynamic type, token/theme types (`Color` extensions, asset catalog color sets with light/dark variants), `ViewBuilder` slots, accessibility modifiers, previews, `XCTest`/`ViewInspector`-style tests, sample apps.
3. **Static inspection (V1).** Leads: literal colors/fonts/paddings in reusable views vs tokens; fixed font sizes instead of text styles or scaled metrics (`@ScaledMetric`, `.font(.body)`); missing `.accessibilityLabel`/`.accessibilityValue`/`.accessibilityHint`/traits on custom controls; `.accessibilityElement(children:)` handling for combined rows; `Image(systemName:)` vs hard-coded glyph text; hard-coded left/right alignment instead of `leading`/`trailing`; `.environment(\.layoutDirection, ...)` usage and previews for RTL; animations without `accessibilityReduceMotion` handling; tap targets built from small frames.
4. **Runtime / gated (V2–V3).** Needs Xcode: `xcodebuild`/`swift build`/`swift test`, previews, Accessibility Inspector, simulator runs with Dynamic Type/RTL/Dark Mode launch arguments. Usually unavailable in a Linux/cloud container.
5. **Idiomatic checks.** SwiftUI composition and modifiers; `leading`/`trailing`; semantic colors and Dynamic Type; `@Environment` for cross-cutting settings; native controls where possible; accessibility modifiers instead of web-style attributes; `Layout`/stacks rather than hard-coded offsets.
6. **False positives.** Fixed sizes for truly fixed artwork; `Color(red:…)` inside a token definition file; custom accessibility traits that the platform requires.
7. **Verification ceiling.** Without a toolchain: V1 only — mark every SwiftUI finding **source-only**. With Xcode available: V2 (tests/build), V3 (simulator/previews/Accessibility Inspector). VoiceOver behavior needs a device or simulator run — say so.
